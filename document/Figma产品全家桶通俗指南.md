## 一、Figma Design · 核心主产品

### 🎨 是什么？
**专业 UI/UX 设计工具**，类似 Photoshop + Sketch，但完全在浏览器里运行、多人实时协作。

### 🏠 生活化比喻
> 就像**建筑师的制图板**：
> - 建筑师在上面画房子的平面图、立面图
> - 每个房间的比例、颜色、材质都精确标注
> - 甲方（产品经理）可以直接在图上写批注
> - 施工队（程序员）可以量取任何尺寸数值

### 📱 在「身后事小程序」里干什么？
| 任务 | 具体操作 |
|------|----------|
| 画首页 | 拖拽组件，精确摆放签到按钮、进度条的位置 |
| 建设计系统 | 定义品牌绿色 #4A7C59，所有页面自动同步颜色 |
| 标注给程序员 | 开发模式下，程序员鼠标悬停就能看到 px、颜色值、字体 |
| 做组件库 | 把「遗嘱卡片」做成可复用组件，改一处全改 |

### 输入 → 输出
```
输入：脑子里的页面想法 + 设计规范 Token（颜色/字体/间距）
输出：精确像素级的 UI 设计稿 .fig 文件
      ↓ 给程序员：标注图 / CSS 代码片段
      ↓ 给产品：可点击原型链接
```

## 二、FigJam · 在线白板

### 🗒️ 是什么？
**数字白板 + 便利贴 + 流程图工具**，像一张无限大的白纸，团队可以同时在上面写写画画。

### 🏠 生活化比喻
> 就像**办公室的那面大白板**：
> - 开需求会议，产品经理把功能模块写在便利贴上
> - 用箭头连起来表示流程关系
> - 大家围着白板讨论，随时擦掉重画
> - 会议结束，白板照片永久保存，不会丢

### 📱 在「身后事小程序」里干什么？
| 任务 | 具体操作 |
|------|----------|
| 信息架构图 | 用卡片 + 箭头画出 5 个 Tab 的层级关系 |
| 用户旅程图 | 画出用户从"第一次打开"到"发布遗嘱"的每一步情绪变化 |
| 头脑风暴 | 团队每人贴便利贴，投票选最重要的 MVP 功能 |
| 流程图 | 画"签到超时触发"的业务逻辑决策树 |

### 输入 → 输出
```
输入：会议讨论内容、Mermaid 代码（可直接导入生成图）
输出：可视化流程图、用户旅程图、投票结果
      ↓ 导出为 PNG/PDF 放进 PRD 文档
      ↓ 直接共享链接给所有人
```

### 🔥 FigJam vs Figma Design 关键区别

| 对比维度 | FigJam | Figma Design |
|----------|--------|--------------|
| 精度 | 随意、不精确 | 精确到像素 |
| 用途 | 讨论、思考、梳理 | 设计、交付、标注 |
| 使用者 | 全员（产品/研发/设计） | 主要是设计师 |
| 阶段 | 项目前期 | 项目中期 |
| 比喻 | 草稿本 | 正式图纸 |

## 三、Figma Slides · 演示文稿

### 📊 是什么？
**在 Figma 里直接做 PPT**，设计稿可以一键转为演示幻灯片，不需要截图复制到 PowerPoint。

### 🏠 生活化比喻
> 就像**把你的设计图册直接变成汇报材料**：
> - 以前：设计稿在 Figma → 截图 → 粘到 PPT → 改了又要重截
> - 现在：设计稿直接在 Figma Slides 里展示，改设计稿，幻灯片自动更新

### 📱 在「身后事小程序」里干什么？
| 场景 | 具体操作 |
|------|----------|
| 向投资人汇报 | 把设计稿 + 用户数据做成融资路演 PPT |
| 需求评审会 | 把 PRD 要点 + 原型截图组合成评审幻灯片 |
| 设计走查 | 设计师展示每个页面的设计决策和思路 |

### 输入 → 输出
```
输入：Figma 设计稿帧（Frame）+ 文字说明
输出：可在线演示的幻灯片，支持演讲者模式
      ↓ 保持和设计稿同步，不需要手动截图
```

### ⚠️ 和 PPT / Google Slides 的区别
```
PowerPoint / Google Slides：
  ✅ 表格、图表功能强大
  ❌ 放设计图需要截图，更新很麻烦

Figma Slides：
  ✅ 设计稿直接嵌入，自动同步
  ✅ 视觉效果更精美（设计师做的）
  ❌ 数据图表功能相对较弱
```

## 四、Figma Make（原 Figma Dev Mode）· 设计转代码

### ⚙️ 是什么？
**设计稿直接生成前端代码**，程序员不用肉眼量尺寸，AI 自动把 UI 稿转成 React / CSS / Swift 代码。

### 🏠 生活化比喻
> 就像**把建筑平面图直接变成施工材料清单**：
> - 以前：施工队看着平面图，自己量：这堵墙 3.5 米，用多少砖
> - 现在：系统自动算好：需要 xxx 块砖、yyy 吨水泥，直接采购

### 📱 在「身后事小程序」里干什么？

**示例：设计稿里画了一个「签到按钮」**

```
Figma Make 自动生成的代码 ↓
```

```css
/* 自动生成的 CSS */
.checkin-button {
  display: flex;
  align-items: center;
  justify-content: center;
  width: 200px;
  height: 48px;
  background: #4A7C59;
  border-radius: 24px;
  font-size: 16px;
  font-weight: 600;
  color: #FFFFFF;
  box-shadow: 0px 4px 12px rgba(74, 124, 89, 0.3);
}
```

```jsx
// 自动生成的 React 组件
const CheckinButton = ({ onClick, disabled }) => (
  <button
    className="checkin-button"
    onClick={onClick}
    disabled={disabled}
  >
    今日签到
  </button>
)
```

### 输入 → 输出
```
输入：Figma Design 设计稿（精确的组件和样式）
输出：CSS / React JSX / SwiftUI / Flutter 代码
      ↓ 程序员直接复制使用，减少 80% 的还原工作
```

### ⚠️ 局限性（为什么不能完全替代程序员）
```
能生成：  外观样式（颜色/尺寸/字体/阴影/圆角）
不能生成：业务逻辑（点击后调什么接口、数据怎么处理）
         复杂交互（列表滚动、手势操作）
         状态管理（登录状态、加载中/报错状态）

结论：Make 解决的是"像不像"，程序员解决的是"能不能用"
```

## 六、回答你的问题：为什么用 FigJam 而不是直接用 Figma？

### 核心答案：**阶段不同，工具不同**

```
项目早期（混沌期）          项目中期（确定期）
用 FigJam ✅               用 Figma Design ✅
│                           │
│ 目的：探索、讨论           │ 目的：精确交付
│ 特点：快、乱、改得快        │ 特点：严谨、有规范
│ 参与者：全员               │ 参与者：主要是设计师
│                           │
│ 产出：流程图、架构图         │ 产出：像素级设计稿
└─────────────────────────────┘
```

### 具体场景对比

**场景 1：画信息架构图**

```
❌ 用 Figma Design 画 IA 图：
   → 要设置精确的框大小、对齐、颜色
   → 改一个节点要重新排布局
   → 费时间在"好不好看"而不是"对不对"

✅ 用 FigJam 画 IA 图：
   → 拖拽卡片，随意连箭头
   → 便利贴随手写，不在乎排版
   → 10分钟画完，团队立刻开始讨论
```

**场景 2：开需求评审会**

```
❌ 用 Figma Design 开会：
   → 设计稿太精细，大家容易纠结颜色对不对
   → 没有投票功能，无法快速决策
   → 不适合实时协作写字

✅ 用 FigJam 开会：
   → 每人贴便利贴说想法
   → 用 emoji 投票 👍 功能决定优先级
   → 计时器功能控制讨论节奏
```

## 七、实际项目中的使用时间线

```
第 1 周：FigJam
  ├── Day 1: 头脑风暴（便利贴 + 投票）
  ├── Day 2: 画信息架构图
  └── Day 3: 用户旅程图 + 流程图

第 2 周：Figma Design
  ├── Day 1-2: 建设计系统（颜色/字体/组件）
  ├── Day 3-4: 画各模块 UI 稿
  └── Day 5: 标注交付给程序员

第 2 周同时：Figma Prototype
  └── 在 Design 稿上连接交互，做可点击原型

第 3 周：Figma Make（可选）
  └── 程序员用 Dev Mode 查看代码和标注

第 N 周：Figma Slides（按需）
  └── 做设计评审 / 投资人演示 PPT
```
